# GCL public web, first integrated concept: non-deploying preview contract

**State:** concept draft; no publication or DNS changes. **Scope:** org-level front-end planning and integration gate, not modification of the existing mathematics site.

## Known public estate

- The existing [Mathematics Programme](https://grandchallenge.github.io/MATH-PROGRAMME/) is the authoritative public documentary site for GCL mathematics.
- Its source is `grandchallenge/MATH-PROGRAMME`, with `mkdocs.yml` and a GitHub Pages workflow that deploys an artifact validated for exact current protected `main`.
- Its public corpus includes current research, domain documentation, campaigns, results, editorial compendia, governance, and reader guides.
- `grandchallenge.ai` is a Grand Challenge Technologies Ltd. property. This document grants no DNS, ownership, or publication changes.
- There is no confirmed GitHub Pages site attached to the `grandchallenge/.github` repository. Do not infer an organization-root Pages site from the existence of project Pages paths.

## Desired public presentation

An illustrated scientific campus front-end with an editorial serif wordmark, warm ivory ground, dense black technical pen-and-ink architectural drawings, marginal handwritten notes, and restrained scientific blue. This is a metaphorical research campus, not a claim about physical facilities. The four user-supplied images remain the governing style reference.

Sections: institutional entrance; research programmes; mathematical frontiers; library and publications; research process; links into source and evidence. Concept art for the NS Number Theory / Noncommutative Geometry campaign must **not** be mislabeled as Navier–Stokes. P vs NP is an open mathematical frontier, not a solved claim.

## Non-stomp requirements

1. Do not alter any file in `grandchallenge/MATH-PROGRAMME`, including `mkdocs.yml`, `docs/`, deployment workflows, route structure, and generated assets, for this concept transaction.
2. Do not configure Pages, CNAME, DNS, redirect, custom domain, production homepage, or workflow deployment.
3. Keep the user-supplied concept source and optimized illustrations in an isolated deliverable until asset intake and preview hosting are selected.
4. Require route-inventory and baseline snapshots for the Mathematics Programme before any integration affecting public paths.
5. Before promoting a candidate, require static asset / anchor checks, real browser checks at desktop and mobile, and accessibility and outbound-link checking. Browser testing was attempted in the drafting environment but blocked by policy (`net::ERR_BLOCKED_BY_ADMINISTRATOR`); visual acceptance is **not** complete.
6. Retain current mathematical claim states and link to authoritative programme records; decorative artwork must never create implied proof or certification.
